# รายงานตรวจและแก้ไขปัญหา SmartCareer

วันที่ 4 ตุลาคม 2026

## ข้อสรุป

พบปัญหาที่กระทบความถูกต้องของแบบทดสอบและข้อมูลที่บริษัทใช้พิจารณาผู้สมัคร รวมถึงคำเตือนจากการตรวจโค้ดที่เคยถูกข้ามตอน build แก้ไขในโค้ดชุดนี้แล้ว และทดสอบกับฐานข้อมูลชั่วคราวที่แยกจากฐานข้อมูลเดิม

## จุดที่พบและการแก้ไข

| จุดที่พบ | ผลกระทบ | การแก้ไข |
| --- | --- | --- |
| แบบทดสอบเริ่มต้นมีข้อความ “ตัวเลือก 1–4” และผ่านการบันทึกได้ | ผู้สมัครอาจได้รับข้อสอบที่ไม่มีคำตอบจริง | เริ่มฟอร์มด้วยช่องว่าง ตรวจหัวข้อ โจทย์ ตัวเลือกที่ไม่ซ้ำ และเฉลยหนึ่งข้อ ทั้งหน้าเว็บและระบบหลังบ้าน |
| แบบทดสอบเดิมที่กรอกไม่ครบยังเริ่มสอบได้ | ผู้สมัครเสียเวลาและอาจส่งคำตอบที่ไม่มีความหมาย | ตรวจความพร้อมก่อนเริ่มจับเวลา และแสดงสาเหตุพร้อมทางกลับไปหน้าการสมัคร |
| ผู้สมัครที่ไม่ได้รับมอบหมายเปิดข้อสอบเฉพาะบริษัทได้ | เนื้อหาข้อสอบอาจรั่ว และผู้สมัครที่ไม่เกี่ยวข้องเริ่มสอบได้ | จำกัดการดูและเริ่มสอบให้ผู้สมัครที่มีใบสมัครที่บริษัทยังพิจารณาอยู่และได้รับข้อสอบผ่านงานหรือการมอบหมาย |
| คำขอรันโค้ดส่งเพียงรหัสโจทย์ | ผู้สมัครอาจทดลองรันโจทย์ของคนอื่นหรือโจทย์จากข้อสอบอื่น | ผูกการรันกับรอบสอบที่กำลังทำ เจ้าของรอบ ประเภทข้อสอบ เวลาสอบ และโจทย์ที่อยู่ในรอบนั้น พร้อมจำกัดขนาดโค้ด |
| แก้โจทย์หรือเฉลยหลังมีผู้เริ่มสอบได้ | คะแนนเก่าอาจเปลี่ยนความหมายเมื่อเฉลยหรือเกณฑ์เปลี่ยน | ล็อกเนื้อหา เวลา และคะแนนผ่านหลังเริ่มสอบ อนุญาตแก้รายละเอียดที่ไม่กระทบคะแนนได้เมื่อโจทย์เดิมเหมือนเดิม |
| การบันทึกเวลาออกจากหน้าสอบเกิดพร้อมกันแล้วข้อมูลหายได้ | ประวัติการสอบไม่ครบ | ทำให้การบันทึกต่อคิวกัน และบันทึกเฉพาะเหตุการณ์จากการซ่อนหน้าข้อสอบจริง พร้อมเวลาในระบบหลังบ้าน |
| หน้าแบบทดสอบมีแถบเตือนซ้ำ และข้อความสรุปว่าเป็นการทุจริต | รบกวนผู้สมัคร และอาจทำให้บริษัทเข้าใจข้อมูลเกินจริง | เหลือแถบเดียว ใช้ข้อความกลาง และรายงานให้ตรวจสอบตามบริบทแทนการติดป้ายว่า “น่าสงสัย” หรือ “เสี่ยงสูง” จากข้อมูลเบราว์เซอร์อย่างเดียว |
| build เคยข้ามการตรวจ lint และยังมีคำเตือนเรื่องรูปกับการโหลดข้อมูล | ปัญหาคุณภาพอาจหลุดไปถึงขั้น build | แก้คำเตือนที่พบทั้งหมด เปลี่ยนรูปในจุดที่ตรวจพบให้ใช้การวางขนาดที่เหมาะสม และเปิด lint ในขั้น build |

ตัวตรวจเนื้อหาแบบทดสอบที่ใช้ร่วมกันอยู่ใน [assessment-validation.ts](../packages/shared/src/assessment-validation.ts) ส่วนหน้าเว็บจะแสดงข้อความบอกเหตุผลแทนการปล่อยให้หน้าสอบว่างเมื่อเปิดไม่ได้

## ผลตรวจหลังแก้

- `npm run lint` ผ่านโดยไม่มีคำเตือนหรือข้อผิดพลาด
- `npm run build` ผ่านทั้ง shared package, API และหน้าเว็บ โดย build ตรวจ lint ด้วย
- `node scripts/verify-core-regression.cjs` ผ่าน 20 กรณี ครอบคลุมการสร้างงาน การสมัคร การบันทึกคำตอบ การส่งสอบ การป้องกันข้อสอบบริษัท การป้องกันการแก้โจทย์ย้อนหลัง และการยืนยันว่าฐานข้อมูลเดิมไม่เปลี่ยน
- ทดสอบหน้าจอด้วย computer-use ในเครื่อง: เข้าบัญชีบริษัททดสอบ เปิดฟอร์มใหม่ ตรวจว่าช่องโจทย์และตัวเลือกว่าง กดบันทึกทั้งที่ยังว่างแล้วระบบหยุดไว้ กรอกโจทย์จริงและบันทึกได้ จากนั้นเข้าบัญชีผู้สมัครทดสอบเพื่อตรวจว่าข้อสอบที่ไม่ถูกมอบหมายและข้อสอบเก่าที่เป็นข้อความตัวอย่างแสดงคำอธิบายและไม่เริ่มจับเวลา

หลักฐานจากการทดสอบรอบล่าสุดอยู่ในเครื่องที่ `output/core-regression/smartcareer_regression_1791123566484/results.json` และ `output/core-regression/smartcareer_regression_1791123566484/invalid-assessment-blocked.png` ผลสรุประบุว่าผ่านครบ 20/20 ไม่มีคำขอ API ที่ล้มเหลว และปิดระบบทดสอบพร้อมลบฐานข้อมูลชั่วคราวแล้ว ไฟล์หลักฐานเหล่านี้ไม่ได้รวมในชุดเผยแพร่

## สิ่งที่ต้องทำกับข้อมูลเดิม

โค้ดใหม่นี้ไม่เปลี่ยนข้อสอบเก่าหรือแก้ข้อมูลบนเว็บจริงโดยอัตโนมัติ ข้อสอบเก่าที่ใช้ข้อความตัวอย่างจะเริ่มสอบไม่ได้จนกว่าบริษัทหรือผู้ดูแลจะสร้างข้อสอบใหม่ที่มีโจทย์และคำตอบจริง หากมีผู้เริ่มสอบข้อสอบชุดนั้นแล้ว ควรสร้างชุดใหม่และมอบหมายชุดใหม่เพื่อไม่เปลี่ยนความหมายของผลสอบเดิม

การตรวจและทดสอบในรายงานนี้ทำในเครื่องกับฐานข้อมูลทดสอบชั่วคราว และไม่ได้เปลี่ยนฐานข้อมูลของเว็บจริง
