# ผลจัดระเบียบค่าตั้งระบบและขั้นตอนเตรียมระบบ

ดำเนินการวันที่ 4 ตุลาคม 2026 — SmartCareer

จัดการข้อ 1–2 ที่เสนอไว้แล้ว: ค่าตั้งระบบที่มีผลต่อการใช้งาน และขั้นตอนสร้างระบบที่ทำซ้ำ การสร้างระบบและการใช้งานหลักในเครื่องตรวจผ่าน ส่วนการเปิดด้วย Docker จริงยังไม่ได้ตรวจ เพราะเครื่องนี้ไม่มี Docker

## สิ่งที่เปลี่ยน

| ก่อนแก้ | หลังแก้ |
| --- | --- |
| ระยะเวลาที่เข้าสู่ระบบค้างไว้ถูกกำหนดตายตัว 7 วัน | อ่าน `JWT_EXPIRES_IN` ที่ตั้งไว้ หากไม่กำหนดใช้ 7 วัน |
| ระบบหลังบ้านอ่านไฟล์ตั้งค่าตามโฟลเดอร์ที่ใช้เปิดโปรแกรม | อ่าน `apps/api/.env` และ `.env` ของโฟลเดอร์หลักจากตำแหน่งแน่นอน โดยค่าที่ส่งให้โปรแกรมโดยตรงมีลำดับสูงสุด |
| ตำแหน่งเก็บจำนวนรายการนำเข้าขึ้นกับโฟลเดอร์ที่เปิดโปรแกรม | ใช้ `apps/api/config` เป็นค่าเริ่มต้น และกำหนดที่เก็บเองได้ด้วย `INGESTION_CONFIG_DIR` |
| ชุดติดตั้งระบบหลังบ้านไม่รวมไฟล์ตั้งค่าการนำเข้า | รวมไฟล์ตั้งค่า และ Compose เก็บค่าที่เปลี่ยนในพื้นที่ถาวร `api_config` |
| ค่า GitHub และ Udemy ในตัวอย่างตั้งค่าไม่ได้ส่งต่อผ่าน Compose | ส่งค่าเหล่านี้ให้ระบบหลังบ้าน พร้อมค่าทางเลือกของบริการประเมินและค้นหางาน |
| สร้างเว็บครั้งหนึ่งเตรียมส่วนใช้ร่วมกันซ้ำ 3 รอบ | เหลือ 1 รอบ เช่นเดียวกับคำสั่งสร้างระบบรวมและสร้างเฉพาะระบบหลังบ้าน |
| ไฟล์ติดตั้งเว็บคัดลอกโฟลเดอร์ `public` ที่ไม่มีในโปรเจกต์ | เพิ่มโฟลเดอร์ที่ติดตามใน Git เพื่อให้ต้นทางการคัดลอกมีอยู่จริง |
| ไม่มีรายการยกเว้นไฟล์สำหรับการสร้าง Docker | เพิ่ม `.dockerignore` ให้ไม่นำไฟล์ความลับ ผลการสร้างเก่า และไฟล์ทดสอบชั่วคราวเข้าไปในชุดสร้าง |

ตัวอย่างตั้งค่าใช้ชื่อ `JUDGE0_BASE_URL` เหมือนกันทั้งเครื่องทดสอบและ production แต่ยังรองรับชื่อเดิม `JUDGE0_API_URL` สำหรับค่าตั้งระบบที่มีอยู่แล้ว ไม่ได้แก้ไฟล์ `.env` จริงหรือไฟล์ตั้งค่าการนำเข้าจริง

ค่าระยะเวลาเข้าสู่ระบบที่เปลี่ยนมีผลกับการเข้าสู่ระบบครั้งใหม่หลังเปิดระบบหลังบ้านใหม่ ส่วนค่าที่อยู่ระบบหลังบ้านของเว็บต้องกำหนดก่อนสร้างเว็บและสร้างใหม่เมื่อเปลี่ยน คำอธิบายและคำสั่งใช้งานอยู่ใน [README](../README.md)

## ผลตรวจ

- `npm run build`: ผ่าน สร้างส่วนใช้ร่วมกันและเตรียมตัวเชื่อมฐานข้อมูลครั้งเดียวก่อนสร้างทั้งสองระบบ
- `npm run build:api` และ `npm run build:web`: ผ่าน เตรียมส่วนใช้ร่วมกันเพียงครั้งเดียวในแต่ละคำสั่ง
- การตรวจชนิดข้อมูลและรายการที่ไม่ได้ใช้ของระบบหลังบ้าน: ผ่าน
- `node scripts/verify-runtime-config.cjs`: ผ่าน ตรวจอ่านค่าตั้งระบบจากทั้งโฟลเดอร์หลักและโฟลเดอร์ระบบหลังบ้าน ค่าที่ส่งตรงให้โปรแกรมมีลำดับสูงสุด และจำนวนรายการนำเข้าที่เปลี่ยนยังอยู่หลังปิดและเปิดโปรแกรมใหม่
- การตรวจไฟล์ติดตั้งเดิมผ่าน และอ่านโครงสร้าง Compose พร้อมตรวจการเชื่อมพื้นที่เก็บค่าถาวรผ่าน ผลนี้ไม่ได้แทนการสร้างหรือเปิด Docker จริง
- การทดสอบการใช้งานหลักในเบราว์เซอร์: ผ่านทั้ง 16 รายการ ไม่มีคำขอจากหน้าเว็บที่ล้มเหลวและไม่มีข้อผิดพลาดขณะหน้าเว็บทำงาน
- ตั้งอายุการเข้าสู่ระบบเป็น 5 นาทีเฉพาะรอบทดสอบ แล้วตรวจข้อมูลการหมดอายุที่ระบบออกให้จริงทุกครั้งที่เข้าสู่ระบบ ผลต่างเท่ากับ 300 วินาทีตามค่าที่ตั้ง
- `git diff --check`: ผ่าน การสร้างเว็บตั้งค่าให้ข้าม lint จึงไม่อ้างว่าตรวจ lint ผ่าน

รอบใช้งานหลักเปิดระบบหลังบ้านจากโฟลเดอร์หลัก ใช้ฐานข้อมูลชั่วคราวแยกต่างหาก แล้วลบฐานข้อมูลทดสอบและหยุดโปรแกรมทั้งหมดเมื่อจบ จำนวนผู้ใช้ งาน และรอบสอบในฐานข้อมูลเดิมก่อนและหลังเท่ากัน การตรวจการบันทึกค่าตั้งระบบเขียนเฉพาะไฟล์ชั่วคราว และยืนยันว่าไฟล์ตั้งค่าการนำเข้าต้นฉบับยังเหมือนเดิม

หลักฐานรอบล่าสุด: [results.json](verification/runtime-setup-2026-10-04.json) ส่วนภาพหน้าจอและบันทึกระบบเก็บเฉพาะในเครื่องที่ตรวจที่ `output/core-regression/smartcareer_regression_1791113417457/`

## งานที่เหลือ

ตรวจการสร้างและเปิดชุด Docker บนเครื่องที่มี Docker ก่อนนำไปติดตั้งจริง จากนั้นจึงตรวจส่วนที่ยังสงสัยว่าไม่ได้ใช้ และเส้นทางที่ยังไม่ครอบคลุม เช่น การสมัครสมาชิกใหม่ บริการเข้าสู่ระบบภายนอก และการประเมินด้วย AI ตามรายการที่เสนอไว้ ยังไม่ได้ลบส่วนเหล่านี้ในรอบนี้
