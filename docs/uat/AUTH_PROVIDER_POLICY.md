# UAT ช่องทางสมัครและเข้าสู่ระบบ — 6 ตุลาคม 2026

ข้อกำหนดใหม่: ผู้สมัครใช้ GitHub เท่านั้น บริษัทใช้ Google เท่านั้น ผู้ดูแลใช้อีเมลและรหัสผ่าน ไม่มีการลบหรือเปลี่ยนข้อมูลบัญชีเดิม ผล UAT รอบก่อนเป็นหลักฐานย้อนหลัง ไม่ใช่ผลรับรองนโยบายใหม่นี้

ใช้บัญชี QA ที่เจ้าของอนุญาต ไม่บันทึกรหัสผ่าน รหัสยืนยัน หรือค่าลับในรายงาน

| กรณี | ขั้นตอนที่ทำผ่านเว็บได้ | ผลที่ต้องได้ |
|---|---|---|
| สมัครผู้สมัคร | เปิด /register เลือกผู้หางาน กดสมัครด้วย GitHub ใช้บัญชี QA ใหม่และทำขั้นตอนผู้ให้บริการ | เปิด /profile เป็นผู้สมัคร ผูกชื่อ GitHub ตรงบัญชี ไม่มีช่องสมัครด้วยอีเมลหรือรหัสผ่าน |
| สมัครบริษัท | เปิด /register เลือกบริษัท กดสมัครด้วย Google ใช้บัญชี QA ใหม่ | เปิด /company/dashboard เป็นบริษัท แก้ไขชื่อและข้อมูลบริษัทได้ภายหลัง ไม่มีช่องสมัครด้วยอีเมลหรือรหัสผ่าน |
| เข้าสู่ระบบผู้สมัคร | ออกจากระบบ เปิด /login กด GitHub ใช้บัญชี QA ผู้สมัครเดิม | กลับเข้าโปรไฟล์เดิม ใบสมัครและผลสอบยังอยู่ |
| เข้าสู่ระบบบริษัท | ออกจากระบบ เปิด /login กด Google ใช้บัญชี QA บริษัทเดิม | กลับบริษัทเดิม งาน ข้อสอบ และใบสมัครยังอยู่ |
| บัญชีเดิมที่สมัครด้วยอีเมล | ใช้ GitHub สำหรับผู้สมัครหรือ Google สำหรับบริษัท โดยใช้อีเมลยืนยันตรงกับบัญชีเดิม | เชื่อมกับบัญชีเดิมโดยไม่สร้างข้อมูลซ้ำ ชื่อ GitHub ที่เคยผูกต้องตรงกัน หากไม่ตรงให้แจ้งข้อผิดพลาด |
| ป้องกันรหัสผ่านบัญชีเดิม | ที่ /login ใช้อีเมลและรหัสผ่านของบัญชี QA ผู้สมัครหรือบริษัทเดิมในช่องสำหรับผู้ดูแล หนึ่งครั้ง | เข้าสู่ระบบไม่ได้ แจ้งให้ใช้ GitHub หรือ Google ตามบทบาท |
| ผู้ดูแล | ที่ /login กรอกบัญชี QA ผู้ดูแลในช่องที่ระบุ Admin | เข้าสู่ /admin/dashboard ได้ รหัสผ่านผิดหนึ่งครั้งต้องแจ้งข้อผิดพลาด |
| ผู้ให้บริการผิดบทบาท | ใช้ปุ่ม Google กับอีเมล QA ที่เป็นผู้สมัคร หรือ GitHub กับอีเมล QA ที่เป็นบริษัท | ปฏิเสธการเข้าสู่ระบบ ไม่เปลี่ยนบทบาทและไม่สร้างบัญชีซ้ำ |
| ยกเลิกการเข้าสู่ระบบ | เริ่มผ่าน GitHub/Google แล้วกดยกเลิกที่ผู้ให้บริการ | แจ้งข้อผิดพลาดและเริ่มใหม่ได้ ไม่เสนอการเข้าสู่ระบบด้วยอีเมลสำหรับบัญชีทั่วไป |
| กลับหน้างาน | ยังไม่เข้าสู่ระบบ เปิดงาน กดสมัคร จากหน้า /login กด GitHub แล้วเข้าสู่บัญชี QA | กลับหน้างานเดิมตามลิงก์ภายในเว็บ |

การตรวจหลังบ้านแยกจาก manual UAT: คำขอสมัครผ่านอีเมลต้องถูกปฏิเสธทั้งสองบทบาท แม้ส่งตรงมาที่บริการ และรหัสผ่านเก่าของบัญชีทั่วไปต้องไม่สร้าง session; ตัวจำลองผู้ให้บริการต้องใช้ไม่ได้ใน production

เอกสาร UAT เก่าที่กำหนดให้สมัครผู้สมัคร/บริษัทด้วยอีเมลหรือใช้รหัสผ่านของบัญชีเหล่านี้ถูกแทนที่ด้วยตารางนี้ ต้องทดสอบใหม่และบันทึกผลจริง ห้ามนำผล PASS เดิมมาอ้างว่า OAuth ใหม่ผ่านแล้ว
