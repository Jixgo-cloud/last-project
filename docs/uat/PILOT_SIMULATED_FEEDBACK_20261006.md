# ผลทดลองใช้งานจำลอง SmartCareer

ผลแก้และตรวจซ้ำภายหลังอยู่ใน [รายงานปรับหน้าจอ](PILOT_UX_FIXES_20261006.md) ข้อสังเกตด้านล่างเก็บเป็นหลักฐานสภาพก่อนแก้

**เป็นการจำลองผู้ใช้โดย AI ตามที่เจ้าของอนุญาต ไม่ใช่คำตอบจากคนจริง** วันที่ 6 ตุลาคม 2026 เวลา 22:14–22:21 ไทย ใช้หน้าจอเว็บจริง บัญชีบริษัท QA และ BADREE ผ่าน Computer Use อ่านผลรอบ R3 ที่มีอยู่แล้ว ไม่สร้างใบสมัคร ไม่เริ่มสอบใหม่ และไม่เปลี่ยนคะแนนหรือสถานะ

ผู้ช่วยมีความรู้จากการตรวจครั้งก่อนและมีลิงก์จากใบงาน จึงไม่ใช้รอบนี้วัดว่าคนที่เห็นเว็บครั้งแรกจะหาเมนูได้เองหรือใช้เวลานานเท่าใด ไม่สร้างคะแนนความพึงพอใจ จำนวนผู้ทดลองจริง หรือคำสัมภาษณ์ขึ้นมา

## ขั้นตอนที่ดำเนินการจริง

| บทบาทและขั้นตอน | สิ่งที่พบจากหน้าจอ |
|---|---|
| บริษัท อ่านใบสมัครเฉพาะงาน R3 | มีสองใบสมัคร BADREE 50% / ปฏิเสธ และ Jixgo-cloud 100% / รับเข้าทำงาน ตัวเลขและชื่องานตรงกัน |
| บริษัท เปิดผลสอบที่ตรวจแล้ว | ทั้งสองรายการเป็น Reviewed 50% และ 100% เปิดรายละเอียด BADREE เห็นคะแนนและเหตุผล QA เดิม ไม่กดบันทึก |
| ผู้สมัคร หาใบสมัคร | ใช้เมนูบัญชี → การสมัครของฉัน พบงาน R3 พร้อมสถานะไม่ผ่านการคัดเลือก คะแนน 50% เกณฑ์ 70% และปุ่มดูผลสอบที่ส่งแล้ว |
| ผู้สมัคร เปิดผลและโหลดใหม่ | แสดงคะแนนหลังตรวจ 50% เกณฑ์ผ่าน 70% ใช้เวลา 7 วินาที โหลดใหม่ยังเป็นผลเดิม ไม่มีเวลานับถอยหลัง |
| ผู้สมัคร อ่านกระดิ่ง | แจ้งเตือนระบุชื่องาน R3 และ REJECTED คลิกนอกกล่องและกด Escape ปิดได้ ไม่กดอ่านแล้วทั้งหมด |
| ผู้สมัคร ค้นหางานและคอร์ส | ค้นหา PILOT-QA-R3 พบหนึ่งงานตรงชุด ค้นหา React ในคลังคอร์สพบหกคอร์ส ไม่เปิดสมัครเพิ่มหรือเริ่มเรียนที่ต้นทาง |

รวม **6 ขั้นตอนในใบงานที่ทำได้ครบตามขอบเขตการอ่านข้อมูลเดิม** ไม่ใช่การผ่านกรณีใหม่ในทะเบียน UAT ผู้สมัคร Jixgo-cloud ไม่ได้เข้าสู่ระบบซ้ำในรอบนี้ ใช้ผลของเขาที่บริษัทแสดงเท่านั้น ไม่รวมบทบาทผู้ดูแล การสมัครบัญชีใหม่ มือถือจริง การซูม หรือการดึงงานตามเวลา

## จุดที่ควรปรับตามลำดับ

### 1 หน้าตรวจข้อสอบปรนัยใช้คำของการตรวจโค้ด

หน้ารายละเอียด BADREE ของข้อสอบ Theory มีหัวข้อ “ตรวจโค้ด & รีวิวผลการสอบ” และช่อง “โค้ดของผู้สมัคร” ซึ่งแสดง “ไม่มีโค้ดที่ส่งมา” คำอธิบายยังกล่าวถึง Sandbox และรายงาน AI ขณะที่รายการคะแนน AI เป็น N/A

**ความเห็นในบทผู้ใช้จำลอง:** เมื่อเปิดตรวจข้อสอบปรนัย ผมอาจเข้าใจว่าผู้สมัครส่งคำตอบไม่ครบ ทั้งที่ผลสอบถูกบันทึกแล้ว

ควรแยกหน้าตรวจตามชนิดข้อสอบ ปรนัยใช้ “ตรวจคำตอบและผลสอบ” แสดงคำตอบรายข้อถ้านโยบายการเปิดเผยอนุญาต และไม่แสดงช่องโค้ดหรือผล AI ที่ไม่ได้ใช้ ข้อสอบ Coding คงข้อมูลโค้ดตามเดิม การแก้ต้องตรวจทั้งสองชนิด ไม่เปลี่ยนผลสอบเก่า

### 2 สถานะภาษาอังกฤษทำให้ต้องตีความเอง

หน้าใบสมัครไทยมีข้อความ “Status updated to REJECTED” กระดิ่งแจ้งชื่อเรื่องไทย แต่สถานะท้ายข้อความเป็น REJECTED ส่วนตัวกรองบริษัทเป็น Applied, Reviewing, Interview, Tech Test, Offer, Accepted และ Rejected

**ความเห็นในบทผู้ใช้จำลอง:** ผมอยากอ่าน “ไม่ผ่านการคัดเลือก” ได้ทันทีโดยไม่ต้องแปลคำเอง

ควรใช้ชื่อสถานะไทยสม่ำเสมอเมื่อเลือก TH และชื่ออังกฤษเมื่อเลือก EN โดยรักษาค่าสถานะที่บริการใช้ไว้ ความหมาย “ผ่านข้อสอบ” ต้องแยกจาก “รับเข้าทำงาน”

### 3 คะแนนหลายประเภทควรอธิบายให้แยกกัน

BADREE เห็นความเหมาะสมกับงาน 94% แต่คะแนนข้อสอบ 50% และเกณฑ์ผ่านข้อสอบ 70% หน้ารายละเอียดงานมีสูตรความเหมาะสมและหน้าบริษัทมีป้าย Match อยู่แล้ว จึงไม่สรุปว่าคำนวณผิดจากตัวเลขที่ต่างกัน

**ความเห็นในบทผู้ใช้จำลอง:** ผมอยากรู้ทันทีว่าทำไมเหมาะกับงานมากแต่สอบไม่ผ่าน

ควรเพิ่มคำอธิบายสั้นว่า “ความเหมาะสมกับงาน” ประเมินจากทักษะและสายงาน ส่วน “คะแนนสอบ” มาจากคำตอบในข้อสอบ และการตัดสินรับเข้าทำงานเป็นอีกขั้นหนึ่ง ไม่เปลี่ยนสูตรคะแนนเพื่อทำให้ตัวเลขตรงกัน

### 4 ผลสอบบอกคะแนนแต่ยังไม่บอกว่าจะพัฒนาตรงไหน

หน้าผลผู้สมัครแสดง 50% และเกณฑ์ 70% ไม่มีข้อความเหตุผลจากผู้ตรวจหรือคำอธิบายรายข้อในหน้าที่เปิดครั้งนี้ จึงทราบผลแต่ไม่ได้คำแนะนำเพิ่มเติม

**ความเห็นในบทผู้ใช้จำลอง:** ผมรู้ว่าคะแนนไม่ถึงเกณฑ์ แต่ยังไม่รู้ว่าควรทบทวนเรื่องใดก่อน

ควรพิจารณาเพิ่มข้อความแนะนำที่บริษัทตั้งใจเปิดเผยให้ผู้สมัคร แยกจากบันทึกตรวจสอบภายในของบริษัท ห้ามนำเหตุผลภายในออกแสดงโดยอัตโนมัติ แก้ใบงานแล้วให้ผู้ทดลองอ่านคะแนนและเกณฑ์ที่มีจริง ไม่สั่งให้อ่านเหตุผลที่หน้านี้ไม่มี

### 5 ข้อมูลระยะเวลาคอร์สบางรายการควรตรวจต้นทาง

ในรายละเอียดงานพบชื่อ “Learn Fetch API In 6 Minutes” แต่ระยะเวลาเป็น 30 mins อีกตัวอย่างในคลังคอร์ส ชื่อ “TypeScript ... 8 Hours” แต่ระยะเวลาเป็น 4 hours ความไม่สอดคล้องนี้เห็นจากหน้าจอ แต่รอบนี้ไม่ได้เปิดวิดีโอต้นทางเพื่อยืนยันความยาวจริง

**ความเห็นในบทผู้ใช้จำลอง:** ผมอาจเลือกคอร์สจากเวลาที่มี จึงต้องรู้ว่าตัวเลขใดเชื่อถือได้

ให้ตรวจข้อมูลต้นทางและที่มาของข้อมูลก่อนแก้ ถ้ายืนยันไม่ได้ให้ระบุว่าไม่ทราบระยะเวลา ไม่เดาค่าขึ้นมา ข้อนี้เป็นรายการรอตรวจความถูกต้องของข้อมูล ไม่ใช่ข้อบกพร่องที่ยืนยันจากต้นทางแล้ว

## สิ่งที่ส่งมอบและผลต่อทะเบียน

บันทึกคำตอบจำลองแยกบทบาทที่ `outputs/pilot-simulation-20261006/simulated-responses.json` ในเครื่อง ระบุ `simulated_ai` ชัดเจน ทั้งสองบทบาทมาจากผู้ช่วยคนเดียว ไม่ใช่ผู้ทดลองจริงสองคน หลักฐานข้อความและภาพสำคัญอยู่ในโฟลเดอร์เดียวกัน ไม่ส่งขึ้น GitHub

ทะเบียน UAT ยังคง **ผ่าน 159 / ติดขัด 26 / ไม่ผ่าน 1** การจำลองนี้ให้ข้อเสนอด้านความเข้าใจและการใช้งาน ไม่ใช้ปิดข้อจำกัดบัญชีใหม่ เอกสารรับรอง บริษัทที่สอง หรือใบสมัครที่หาย ยังไม่มีการแก้หน้าผลสอบหรือข้อมูลคอร์สในรอบนี้

ใช้ข้อ 1–3 เตรียมงานปรับหน้าจอก่อน ข้อ 4 ต้องกำหนดข้อมูลที่เปิดเผยต่อผู้สมัคร และข้อ 5 ต้องตรวจต้นทางก่อนตัดสินแก้จริง เก็บรายงานนี้แยกจากแบบบันทึกของคนจริงที่จะได้ภายหลัง
