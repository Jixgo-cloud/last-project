# แก้การลบประวัติใบสมัคร — 7 ตุลาคม 2026

แก้และเผยแพร่การป้องกันข้อมูลหายแล้ว ตรวจเว็บจริงด้วยงาน QA ใหม่ผ่าน แต่ **ใบสมัคร QUOTA เดิมยังไม่ได้กู้คืน** จึงคง CAN-011 ไม่ผ่านตามทะเบียนเดิม ผลรวมยังเป็น **ผ่าน 184 / ติดขัด 0 / ไม่ผ่าน 1 / ข้าม 1**

## สิ่งที่แก้

พบช่องทางเพิ่มเติมจากโค้ด: ปุ่มลบงานของบริษัทเคยลบงานพร้อมใบสมัครและประวัติที่ผูกอยู่ได้ การพบช่องทางนี้ไม่ได้ยืนยันว่าเป็นช่องทางที่ทำให้ QUOTA เดิมหายในเหตุการณ์ก่อนหน้า

- บริษัทลบงานที่มีประวัติใบสมัครไม่ได้ ทุกสถานะและทุกรอบนับเป็นประวัติ รวมใบสมัครที่ยกเลิกแล้ว ให้ใช้ปิดรับสมัครแทน
- หน้างานปิดปุ่มลบและแสดงเหตุผล บริการตรวจสิทธิ์เจ้าของและจำนวนใบสมัครอีกครั้ง ไม่อาศัยปุ่มปิดเพียงอย่างเดียว
- ล็อกแถวงานครอบคลุมการตรวจและลบในรายการเดียวกัน ป้องกันใบสมัครที่กำลังบันทึกพร้อมคำขอลบหลุดจากการตรวจ ไม่เปลี่ยนโครงสร้างฐานข้อมูลหรือสิทธิ์ฐานข้อมูล
- งานไม่มีใบสมัครยังลบได้ตามขั้นตอนยืนยันเดิม การคัดกรองงานปิดรับ/หมดอายุยังเก็บงานและประวัติไว้ตามฉบับแก้ก่อนหน้า

โค้ดฉบับทดสอบ `fec210ebbe85488bf5754a3676b944b64c444f3a` เผยแพร่ Vercel และ Railway production สำเร็จ Health ของ API จริงแสดง revision เดียวกันและฐานข้อมูล connected

## ผลตรวจ

สร้างโปรเจกต์และ lint ผ่าน ชุดทดสอบหน่วย/ความปลอดภัย **94 กรณีผ่าน** ชุดตรวจหน้าจอและกระบวนการในระบบแยก **44 กรณีผ่าน** รวมการสมัครพร้อมลบงานโดยใช้ฐานข้อมูลจริงในระบบแยก การปฏิเสธการลบงานมีใบสมัคร การลบงานว่าง การตรวจสิทธิ์บริษัท และการรักษาประวัติหลังคัดกรอง [CI รอบที่ตรวจ](https://github.com/Jixgo-cloud/last-project/actions/runs/37621908263)

ตรวจเว็บจริงด้วยบริษัทและผู้สมัคร QA ที่เจ้าของอนุญาต ใช้ฟอร์มจริงสร้างงาน **UAT-CAN011-RETENTION-20261007 — ทดสอบเท่านั้น** และยื่นใบสมัครหนึ่งรอบ ไม่ใช่งานจริงหรือการกู้ข้อมูลเดิม การสร้างงานและยื่นใบสมัครเริ่มก่อน API ฉบับใหม่พร้อม ส่วนการตรวจปุ่มลบและขั้นตอนต่อไปทำหลังยืนยัน revision ใหม่แล้ว

1. เมื่อมีใบสมัครหนึ่งรายการ ปุ่มลบปิดพร้อมข้อความให้ปิดรับเพื่อเก็บประวัติ ไม่กดลบถาวรบนเว็บจริง
2. เปลี่ยนสถานะผ่านเว็บเป็นกำลังพิจารณา → นัดสัมภาษณ์ → ได้รับข้อเสนอ → รับเข้าทำงาน โหลดใหม่ฝั่งบริษัทแล้วยังเป็นสถานะเดิม
3. โควตา 1/1 แสดง Auto-Closed งานและใบสมัครหนึ่งรายการยังอยู่ ปุ่มลบยังปิด
4. เข้าบัญชีผู้สมัครผ่าน GitHub หน้าใบสมัครยังแสดงงาน QA สถานะรับเข้าทำงานและขั้นตอนการคัดเลือกหลังโหลดใหม่ กระดิ่งมีการแจ้งเตือนครบสี่สถานะที่บริษัทเปลี่ยน
5. ตรวจฐานข้อมูลเฉพาะรายการ QA แบบอ่านอย่างเดียว ยืนยันประวัติห้ารายการ APPLIED, REVIEWING, INTERVIEW, OFFER, ACCEPTED งานปิดรับและใบสมัครหนึ่งรายการคงอยู่ หน้าผู้สมัครแสดงสถานะล่าสุดและแผงขั้นตอน ไม่อ้างว่ามีรายการประวัติย้อนหลังทั้งหมดให้กดบนหน้าจอ

หลักฐานและภาพเก็บเฉพาะในเครื่องที่ `outputs/uat-retention-production-20261007/` ไม่ส่งภาพ บัญชี หรือสำรองขึ้น GitHub ไม่รันการคัดกรองทั้งระบบจริงเพื่อทดสอบรอบนี้

## ข้อจำกัดที่ยังเหลือ
