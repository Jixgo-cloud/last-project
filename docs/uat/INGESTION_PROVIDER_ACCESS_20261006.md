## JSearch — ADM-038

- ทดสอบคีย์เดิมใน `apps/api/.env` ด้วยคำขออ่าน `/search` หนึ่งครั้งไปยัง `https://jsearch.p.rapidapi.com` โดยไม่เขียนฐานข้อมูล ได้ HTTP 200 และรายการ 10 งาน บันทึกเฉพาะสถานะและจำนวน ไม่แสดงหรือเก็บคีย์ในผลตรวจ
- พบโค้ดเลือก `RAPIDAPI_KEY` ก่อน `JSEARCH_API_KEY` จึงแก้ให้คีย์เฉพาะ JSearch มีลำดับก่อน ตัดช่องว่างทั้งสองค่า และใช้คีย์ทั่วไปเมื่อไม่มีคีย์เฉพาะหรือคีย์เฉพาะมีแต่ช่องว่าง
- เพิ่มการตรวจอัตโนมัติว่าคีย์ทั่วไปไม่ทับคีย์เฉพาะ และกรณีไม่มีคีย์ไม่เรียกผู้ให้บริการ ยังคงการตรวจ 401/403/429 ว่าไม่มีข้อความหรือคีย์จากผู้ให้บริการหลุดออกไปและไม่สร้างงานตัวอย่าง
- ต้องตั้ง `JSEARCH_API_KEY` ใน soothing-love → production → @smartcareer/api บน Railway โดยใช้คีย์เดิมที่ทดสอบได้ ผู้ใช้กรอกและบันทึกเอง ไม่ส่งคีย์ในแชต ไม่ต้องสร้างหรือซื้อคีย์ใหม่ในขั้นนี้
- หลังเผยแพร่ต้องทดสอบผ่านหน้าผู้ดูแล: เริ่มรอบ ตรวจผลจริง จำนวนเพิ่ม/ซ้ำ/ผิดพลาด และข้อมูลแหล่งงาน จากนั้นเริ่มรอบใหม่เพื่อตรวจรายการซ้ำ คงโควตาเดิม 15 จนมีเหตุให้เปลี่ยน

ตรวจต่อบน API `5b37e28` เวลา 16:31:18 น. โควตา 15 ได้ `JSEARCH_CONNECTION_FAILED` เพิ่ม 0 ซ้ำ 0 ผิดพลาด 1 จึงยังไม่ผ่าน แต่ไม่ใช่ข้อความขาดคีย์แล้ว ทดสอบอ่านสองหน้าจากเครื่องพัฒนาได้ HTTP 200 จำนวน 17 รายการใน 6,381 มิลลิวินาที โดยไม่เขียนฐานข้อมูล ยังไม่ยืนยันสาเหตุการเชื่อมต่อจาก Railway จากผลในเครื่อง ปรับเวลารอ JSearch จาก 10 เป็น 30 วินาทีให้ยังมีขอบเขต และแยก `JSEARCH_TIMEOUT`, `JSEARCH_INVALID_URL`, `JSEARCH_DNS_FAILED` จากความขัดข้องการเชื่อมต่อทั่วไป โดยตรวจเฉพาะรหัสผิดพลาดที่กำหนดไว้ ไม่แสดงที่อยู่ภายในหรือข้อมูลคีย์ ต้องทดสอบหลังเผยแพร่การปรับนี้อีกครั้ง

ตรวจหลังเผยแพร่ API `5bbb34db1ee0a94e2684d9fa766c0b0991a9e09b` แล้ว: [GitHub Actions รอบ 37444041672](https://github.com/Jixgo-cloud/last-project/actions/runs/37444041672) ผ่านครบทั้งการสร้างโปรเจกต์ ชุดตรวจ 54 กรณี ฐานข้อมูลแยก และหน้าจอ 41 รายการ Health รายงาน `ok`, ฐานข้อมูล `connected` และ revision ตรงฉบับนี้ Vercel deployment `dpl_ATwmCKUQtERiwd5KAe6dozvWn5rC` เป็น READY และอ้างอิง commit เดียวกัน หน้าเว็บที่โหลดใหม่ระหว่างรอบใช้ฉบับนี้
