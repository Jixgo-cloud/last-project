# ผลตรวจส่วนที่ทำต่อได้ก่อน — 6 ตุลาคม 2026

ตรวจต่อหลัง Blognone ผ่าน โดยคงบัญชีและข้อมูลบนเว็บจริงไว้ ส่วนกรณีบริการขัดข้องใช้ระบบทดสอบในเครื่องที่แยกฐานข้อมูลและบัญชีทั้งหมดตามแผน ไม่ทำให้ Railway, Judge0 จริง หรือคิวรับรองจริงล่ม

## ข้อบกพร่องที่พบและแก้

เมื่อบริการรันโค้ดตอบ HTTP 503 ข้อความ `Code evaluation server is currently unavailable. Please retry in a few moments.` ไม่มีคำว่า Judge0 หรือเลข 503 อยู่ในข้อความ หน้า Coding จึงแสดงกล่องแจ้งเตือนทั่วไป ทั้งที่เตรียมข้อความบริการไม่พร้อมไว้แล้ว ตัวรับข้อมูลเก็บสถานะ HTTP ถูกต้อง แต่หน้าสอบตรวจเฉพาะข้อความ

แก้ให้ใช้สถานะ HTTP 503 และ 429 เป็นหลัก ทั้งตอนทดสอบโค้ดและส่งคำตอบ คงการรองรับข้อความเดิมเมื่อไม่มีสถานะ ไม่จัดข้อผิดพลาด 401/422 เป็นบริการขัดข้องเพียงเพราะข้อความมีชื่อ Judge0 สูตรคะแนนและการให้สิทธิ์สอบคงเดิม

|---|---|---|

## ทะเบียนและงานที่ยังพัก

ตามขอบเขตแผนที่ให้จำลองความขัดข้องในสภาพแวดล้อมแยก รอบนี้ปิด CAN-037 และ ADM-050 เป็น **ผ่านในระบบแยก** พร้อมบันทึกสภาพแวดล้อมไว้ในทะเบียน ไม่อ้างว่าได้เห็นบริการภายนอกขัดข้องบนเว็บจริง

ทะเบียนครบ 186 กรณี: **ผ่าน 158 / ติดขัด 27 / ไม่ผ่าน 1** เพิ่มสองผลผ่านจากการทดสอบแยกครั้งนี้ ประวัติผลติดขัดและข้อผิดพลาดก่อนแก้ยังอยู่ ไม่แปลงผลจำลองของการสมัครบัญชีใหม่ กระดิ่งว่าง หรือรหัสผู้ดูแลเป็นผลผ่านบนเว็บจริง

GEN-010/011 และ CAN-002 ยังคงติดขัดตามขอบเขตปัจจุบัน: ฟอร์มสมัครด้วยอีเมลและการผูก GitHub ครั้งแรกด้วยฟอร์มเดิมไม่มีแล้ว การกลับบัญชีเดิมผ่าน GitHub/Google เคยตรวจผ่านบางส่วน แต่ไม่แทนการเชื่อมบัญชีด้วยอีเมลตรงกัน การผูกในบัญชีใหม่ หรือเงื่อนไขผู้ดูแลที่ยังไม่ครบ

ยังพักบัญชีใหม่ บริษัท QA แห่งที่สอง เอกสารรับรอง การลบรายการที่ยังไม่ยืนยัน การล้างคอร์สที่ปะปนข้อมูลจริง การซูมจริง 200% และการกู้ใบสมัคร CAN-011 ส่วนรอบดึงงานเที่ยงคืนหลังแก้ Blognone ยังไม่ถึงเวลาในรอบตรวจนี้ ไม่เปลี่ยนเวลาเครื่องหรือกดนำเข้าด้วยมือแล้วนับเป็นรอบอัตโนมัติ

ปรับใบงานผู้ทดลองให้ระบุ JobsDB/Blognone ว่าดึงตรงผ่านแล้ว ใช้ทดลองค้นหาและอ่านประกาศได้ ส่วนรอบสมัครและสอบใหม่ยังต้องเตรียมชุดงานใหม่ตามใบงาน ไม่ใช้ชุดที่รับครบแล้ว

หลักฐานก่อน/หลังและผลทำความสะอาดอยู่ใน `outputs/remaining-isolated/` เก็บในเครื่อง ไม่ส่งขึ้น GitHub
