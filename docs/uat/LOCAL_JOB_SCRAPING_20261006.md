# ดึงงานจากเครื่องและนำเข้า SmartCareer

วิธีนี้แยกการอ่านหน้าแหล่งงานออกจากการบันทึกบน Railway ใช้ไฟล์ JSON ที่มีประกาศจริง ไม่ใช้บัญชีต้นทาง คุกกี้ โทเคน หรือค่าลับในไฟล์

## ขอบเขตที่ต้องเข้าใจ

Railway อ่าน JobsDB และ Blognone ด้วย HTTP/Chromium แล้วได้ 403 การลอง Chromium อัตโนมัติในเครื่องกับ Blognone รอบนี้ก็ได้ 403 แต่หน้าที่เปิดตามปกติใน Codex Browser แสดงประกาศจริงได้ จึงใช้ Computer Use อ่านเฉพาะ DOM ของการ์ดงานสาธารณะ แล้วให้ตัวแยกข้อมูลในโปรเจกต์สร้างไฟล์นำเข้า วิธีนี้ยังต้องมีการเปิดหน้าที่อ่านได้ ไม่ใช่การแก้ให้รอบอัตโนมัติบน Railway เข้าถึงต้นทางได้แล้ว

ไฟล์มีข้อมูลจากการ์ดประกาศ เช่น ชื่องาน บริษัท ข้อความสั้น สถานที่ ประเภทงาน เงินเดือนที่ตัวอ่านรองรับ และลิงก์ต้นทาง ไม่รับรองว่าเป็นรายละเอียดเต็มหรือประกาศยังเปิดรับที่ต้นทางทุกงาน JobsDB ปัจจุบันยังไม่แยกเงินเดือนจากการ์ด จึงคงเป็นค่าว่าง

## สร้างไฟล์จากตัวดึง

รันจาก `D:/Workshop/last-project` หลังสร้าง API แล้ว:

```powershell
npm run build:api
node scripts/export-local-jobs.cjs --source JOBSDB --limit 10 --out outputs/local-jobs/jobsdb-round.json
node scripts/export-local-jobs.cjs --source BLOGNONE --limit 5 --out outputs/local-jobs/blognone-round.json
```

สคริปต์ใช้ Chromium ใหม่ที่ไม่มีบัญชีเข้าสู่ระบบ หากมี Chrome/Edge ในตำแหน่งมาตรฐานจะใช้โปรแกรมนั้น แต่ไม่ใช้ profile ของผู้ใช้ หากต้นทางตอบ 403 จะหยุดและไม่สร้างข้อมูลตัวอย่างหรือทับไฟล์เดิม

## ใช้หน้าที่เปิดและอ่านได้จริง

ให้ Computer Use เปิด [JobsDB](https://th.jobsdb.com/jobs?keywords=developer) หรือ [Blognone Jobs](https://jobs.blognone.com/search) แล้วตรวจว่าแสดงการ์ดงาน ไม่ใช่หน้าตรวจสอบการเข้าถึง บันทึกเฉพาะ outerHTML ของการ์ดประกาศเป็นไฟล์ `.html` ใน `outputs/local-jobs/` ไม่ส่งทั้งหน้า script, browser storage หรือ cookies

ตัวเลือก DOM ที่ยืนยันในรอบนี้: JobsDB `[data-testid="job-card"]` และ Blognone `a.card[href*="/job/"]` จากนั้นรัน:

```powershell
node scripts/export-local-jobs.cjs --source JOBSDB --limit 10 --html outputs/local-jobs/jobsdb-fresh-cards.html --out outputs/local-jobs/jobsdb-round.json
node scripts/export-local-jobs.cjs --source BLOGNONE --limit 5 --html outputs/local-jobs/blognone-fresh-cards.html --out outputs/local-jobs/blognone-round.json
```

โหมด HTML ไม่เรียกเครือข่ายเพิ่มหรือรัน JavaScript ในไฟล์ ใช้เวลาบันทึก HTML เป็นเวลารวบรวมข้อมูล เพื่อไม่รายงานไฟล์เก่าว่าเพิ่งดึงสด รองรับเฉพาะไฟล์การ์ดสาธารณะที่เก็บไว้จริง ไม่อ่านไฟล์ `.env` หรือข้อมูลบัญชี

## นำเข้าบนเว็บ

1. เข้าสู่ระบบแอดมิน แล้วเปิด `/admin/ingestion`
2. ใน “นำเข้างานที่ดึงจากเครื่อง” เลือกไฟล์ JSON ที่สคริปต์สร้าง
3. ตรวจรายการ ชื่อบริษัท ลิงก์ จำนวนทั้งหมด และจำนวนงานเดิม ตัวอย่างยังไม่เขียนข้อมูล
4. กด “ยืนยันนำเข้าไฟล์นี้” แล้วรอผล รอบถูกบันทึกในฐานข้อมูลและติดตามต่อได้หลังโหลดใหม่
5. หากคำขอขาดการเชื่อมต่อก่อนมีรหัสรอบ ให้เลือกไฟล์เดิมและส่งคำขอเดิม ไม่เริ่มรอบอื่นแทน
6. ตรวจประวัติ `JOBSDB_LOCAL_FILE` หรือ `BLOGNONE_LOCAL_FILE` และรายการงานสาธารณะ การส่งไฟล์เดิมในรอบใหม่ต้องนับงานเดิม ไม่เพิ่มซ้ำ

ตรวจสิทธิ์แอดมินทั้งการดูตัวอย่างและเริ่มนำเข้า จำกัดไฟล์ 256 KB/60 งาน และจำกัดตามแหล่ง JobsDB สูงสุด 60, Blognone สูงสุด 30 ข้อมูลไม่เกิน 7 วัน ลิงก์ต้องเป็น HTTPS บนโดเมนของแหล่งที่ระบุ รหัสงานต้องตรงกับลิงก์ ไม่รับข้อมูลเจ้าของงานหรือคำสั่งเปลี่ยนสิทธิ์ ไม่ลบหรือเปิดงานเดิมกลับโดยอัตโนมัติ

การตรวจ URL/รหัสและผู้ส่งแอดมินช่วยควบคุมความถูกต้อง แต่ไม่ได้ยืนยันต้นทางด้วยลายเซ็น เจ้าของระบบต้องใช้ไฟล์ที่ดึงจากหน้าเว็บจริง ไม่ใช่แก้ไฟล์ให้เป็นประกาศที่ไม่มีอยู่

## ผลรอบนี้

เตรียมไฟล์จากหน้าที่เปิดจริงได้ JobsDB 10 และ Blognone 5 งาน ตรวจข้อมูลและลิงก์ผ่านแล้ว ชุดตรวจอัตโนมัติ 61 รายการผ่านในเครื่อง การนำเข้าบนเว็บจริงและการส่งซ้ำยังรอเผยแพร่ ไม่เปลี่ยนสถานะ ADM-039–040 เป็นผ่านจากการสร้างไฟล์อย่างเดียว

ผลการอ่านตรงจาก Railway ที่ยังได้ 403 เก็บใน [รายงานเดิม](AUTHORIZED_SCRAPING_RETEST_20261006.md) ส่วนทะเบียน UAT 186 กรณีรักษาหลักฐานเดิมทั้งหมด ไฟล์ HTML/JSON และภาพอยู่ใน outputs เท่านั้น ไม่ส่งขึ้น GitHub
