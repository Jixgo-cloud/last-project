# ผลแก้ตัวดึง JobsDB และ Blognone บน Railway

ตรวจวันที่ 6 ตุลาคม 2026 เวลาไทย ผลล่าสุดบน API **988223a: Blognone ผ่านการดึงตรงจาก Railway และดึงซ้ำ** เพิ่มจริง 8 พบเดิม 5 ผิดพลาด 0 รอบซ้ำเพิ่ม 0 พบเดิม 13 ผิดพลาด 0 JobsDB ผ่านอยู่แล้ว

## สิ่งที่แก้และเผยแพร่

- เพิ่มการอ่านหน้าเว็บสาธารณะด้วย HTTP/2 ปกติ เมื่อ HTTP เดิมตอบ 403 จำกัดเวลา 15 วินาที ขนาด 25 MiB และการเปลี่ยนปลายทางไม่เกิน 3 ครั้งภายในเว็บต้นทางเดียวกัน
- รอประกาศงานจริงเมื่อเบราว์เซอร์ได้รับหน้า 403 ระหว่างโหลด ตรวจปลายทางอีกครั้ง และปิดเบราว์เซอร์เสมอ ไม่ลองผ่านเบราว์เซอร์เมื่อพบ 429
- อนุญาตทรัพยากรของ API สาธารณะ Blognone ที่ตรวจพบในเว็บไซต์จริง ไม่อ่านบัญชีหรือค่าลับของเบราว์เซอร์
- เมื่อหน้ารวม Blognone ยังตอบ 403 ให้ลองอ่านประกาศจริงบนหน้าแรกสาธารณะครั้งเดียว หน้านี้มีรายการน้อยกว่าหน้ารวม โควต้าเป็นเพดาน ไม่ใช่จำนวนที่รับประกัน
- เพิ่ม Chrome แบบปกติบนจอชั่วคราวของ Railway เฉพาะ Blognone ผ่านการตรวจเปิด–ปิดจริงใน CI และทดสอบนำเข้าจริงสองรอบ โหมด JobsDB คงเดิม
- ย้าย API จาก US West ไป Southeast Asia (Singapore) โดยคง 1 replica ขีดจำกัด 2 vCPU/1 GB และฐานข้อมูลเดิม โหมด Serverless ปิดอยู่

ไม่มีการใช้ไฟล์จากเครื่องเป็นข้อมูลนำเข้าในรอบนี้ ไม่มีตัวกลางอ่านแทน ไม่มีการหมุน IP ซ้ำ ปรับแต่งลายนิ้วมือเบราว์เซอร์ แก้ CAPTCHA หรือปิดการตรวจใบรับรอง TLS งานเดิมยังอยู่เมื่ออ่านต้นทางไม่สำเร็จ

## การดึงอัตโนมัติและข้อจำกัด

หน้าเว็บ Blognone เผยแพร่ [API สาธารณะ](https://jobs-api.blognone.com/graphql) และคำขออ่าน `getHome` ใน [JavaScript ของเว็บไซต์](https://jobs-static-prod.blognone.com/static/js/bundle.fdc121b4.js) ตรวจคำขออ่าน `home_jobs` โดยไม่ใช้บัญชี โทเคน หรือคุกกี้ ได้ 8 ประกาศจริงในเครื่อง เทียบชื่อ บริษัท เงินเดือน ประเภทงาน รหัส และลิงก์กับ HTML หน้าแรกแล้วตรงทั้งหมด API นี้เป็นรายการบนหน้าแรก ไม่ใช่รายการค้นหาทั้งหมด โควต้าเป็นเพดานและไม่รับประกันว่าจะได้ครบ 15 รายการ

รุ่น e51da7e อ่าน API สาธารณะเมื่อหน้ารวมตอบ 403 และใช้ HTTP/2 ปกติเมื่อ HTTP เดิมของ API ตอบ 403 อีกครั้ง จำกัด API ที่ปลายทางเดียว เวลา 12 วินาที ขนาด 2 MiB ไม่ตาม redirect และไม่ลองต่อเมื่อพบ 429 ข้อมูลขาด รูปแบบเปลี่ยน หรือคำขอ GraphQL มีข้อผิดพลาด ตรวจชื่อและรหัสบริษัท ลิงก์ ประเภทงาน และช่วงเงินเดือนก่อนส่งงานไปบันทึก เงินเดือนแบบต่อรองหรือไม่เปิดเผยเก็บเป็น null งานเดิมไม่ถูกแทนที่

รุ่น 988223a ใช้ [Chrome แบบมีหน้าต่างตามตัวเลือกมาตรฐานของ Puppeteer](https://pptr.dev/guides/headless-modes) เฉพาะ Blognone เมื่อกำหนด `JOB_SCRAPER_BROWSER_MODE=headful` ผ่าน `railpack.json` เพิ่ม Xvfb โดย [คงแพ็กเกจเดิมของ Railpack](https://railpack.com/guides/installing-packages/) จอเป็นของรอบอ่านนั้นโดยเฉพาะ ไม่เปิดรับการเชื่อมต่อ TCP ไม่ใช้หน้าต่างหรือบัญชีของผู้ใช้ ปิดทั้งเบราว์เซอร์และจอเมื่อสำเร็จหรือผิดพลาด คงสัญญาณการทำงานอัตโนมัติของ Chrome ตามปกติ และไม่คลิกหรือแก้ขั้นตอนตรวจสอบหน้าเว็บ โหมด JobsDB คงเดิม การตรวจใน CI ใช้หน้า HTML ภายในชุดตรวจ ไม่ใช่ผลผ่านของการอ่าน Blognone จาก Railway

ระบบเดิมตั้งดึงงานทุกวัน 00:00 น. เขตเวลา Asia/Bangkok และเรียก `syncJobs` ชุดเดียวกับรอบที่ตรวจ ตัวดึงที่แก้จึงใช้ในรอบอัตโนมัติด้วย ตรวจการเรียกจากตัวตั้งเวลาในสภาพแวดล้อมแยกแล้ว แต่ยังไม่ได้สังเกตรอบเที่ยงคืนหลังเผยแพร่รุ่นนี้ ไม่รับประกันว่ากฎหรือหน้าเว็บต้นทางจะไม่เปลี่ยนในอนาคต

ADM-039 ผ่านอยู่แล้ว และรอบนี้เปลี่ยน ADM-040 เป็นผ่าน ผลรวม **ผ่าน 156 / ติดขัด 29 / ไม่ผ่าน 1 จาก 186 กรณี** ประวัติ 403 เดิมเก็บไว้ ไม่เปลี่ยนใบสมัครที่หาย CAN-011 หรือผลกรณีอื่น

ผลผ่านนี้ยืนยันการดึงตรงและการดึงซ้ำของรุ่นที่ระบุ ไม่รับประกันการเชื่อมต่อทุกครั้งในอนาคต หากต้นทางเปลี่ยนหน้าเว็บหรือปฏิเสธคำขอ ระบบยังต้องแสดงความล้มเหลวและเก็บงานเดิมไว้ การตั้งเวลาเที่ยงคืนใช้ตัวดึงชุดเดียวกัน แต่ยังไม่ได้เห็นรอบอัตโนมัติหลังเผยแพร่รุ่นนี้
