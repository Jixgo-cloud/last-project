# Company verification status — 5 October 2026

Company rows previously defaulted to PENDING on registration, before any verification request existed. The dashboard and profile therefore incorrectly said that documents were awaiting administrator review.

Both pages now derive their display from the company's stored review outcome and actual verification requests. A company with no request displays “ยังไม่ส่งเอกสาร”. Submitted requests display “รอตรวจสอบเอกสาร”; verified and rejected companies display their respective outcomes. Rejected companies can correct and resubmit documents. Pending and verified profiles disable another submission in the form.

This is a frontend display correction. Existing stored statuses, identity documents, administrator queue queries and authorization rules are unchanged; no data migration or fabricated production verification request is needed.

Validation: production build and lint passed. The isolated browser regression now has 24 checks, including submission with a disposable screenshot attachment, administrator rejection, resubmission and approval, plus confirmation that a company without a request has no review-queue entry. Computer-use checks confirmed the verified profile and disabled submission button. Regression data is disposable and is never seeded into production.

## Submission hardening — 5 October 2026

The API and form now require an ASCII numeric registration/tax number of exactly 13 digits, plus 1–5 PDF, JPEG or PNG attachments. Raw attachments may total at most 3 MiB, leaving room for base64 encoding and metadata within [Vercel's 4.5 MB function payload limit](https://vercel.com/docs/functions/limitations). Empty files, invalid nested fields, inconsistent declared size, noncanonical base64, mismatched MIME type and incorrect file signatures are rejected before saving. These checks validate the upload structure and basic format; they do not establish the authenticity of the company or fully parse document content.

The frontend checks file count and combined size before reading, disables controls during reading/submission, and shows errors within the form. Existing frontend metadata is accepted during rolling deployment, but timestamps and registration metadata are generated by the server.

Submissions and administrator reviews lock the same company row inside a database transaction. A pending or verified company cannot submit another request; rejected companies can resubmit. Only a pending, latest request can be reviewed, preventing repeated or stale reviews from overwriting a newer outcome. No schema migration or production identity submission is required.

Validation: build and lint passed; 9 security checks and 27 isolated regression checks passed. Regression covers API rejection cases, four simultaneous submissions (one creation and three conflicts), simultaneous reviews (one success and one conflict), stale-review rejection and resubmission/approval. A maximum-size upload serializes below Vercel's 4.5 MB limit. Production identity verification still requires genuine company information and documents.

Follow-up: the administrator list still embeds document contents for every request. Several large requests can exceed Vercel's response limit. Move document retrieval out of the list, add pagination, and use authenticated per-document downloads or private file storage before scaling the review queue.
