# คู่มือเข้าใจระบบ SmartCareer แบบละเอียด

เอกสารนี้อธิบายว่า SmartCareer ทำงานอย่างไร ข้อมูลจากผู้สมัครและบริษัทเดินทางผ่านส่วนใดบ้าง และแต่ละส่วนของระบบรับผิดชอบอะไร เขียนให้อ่านได้โดยไม่ต้องมีพื้นฐานการเขียนโปรแกรม ชื่อภาษาอังกฤษในวงเล็บเป็นชื่อที่ใช้ในโค้ด เผื่อต้องการค้นหาไฟล์ประกอบ

ถ้าต้องการดูภาพรวมโฟลเดอร์และฐานข้อมูลแบบย่อ ให้ดู [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md)

## 1. SmartCareer ทำอะไร

SmartCareer เชื่อมคนหางานกับบริษัทที่กำลังรับสมัคร โดยรวบรวมข้อมูลทักษะจากโปรไฟล์, GitHub และแบบประเมิน นำไปเทียบกับทักษะที่ตำแหน่งงานต้องการ จากนั้นช่วยให้ผู้สมัครติดตามใบสมัครและหาแนวทางเรียนรู้ทักษะที่ยังขาด

มองระบบเป็นสี่ส่วนใหญ่ ๆ ได้ดังนี้

| ส่วน | เปรียบเทียบง่าย ๆ | ตัวอย่างงาน |
|---|---|---|
| หน้าเว็บ (apps/web) | เคาน์เตอร์ที่คนใช้ติดต่อระบบ | กรอกโปรไฟล์ ค้นงาน ดูผลคะแนน และจัดการผู้สมัคร |
| API (apps/api) | ทีมงานที่รับคำขอและทำตามกติกา | ตรวจสิทธิ์ คำนวณคะแนน บันทึกใบสมัคร และจัดการข้อมูล |
| ฐานข้อมูล (PostgreSQL ผ่าน Prisma) | ตู้เก็บประวัติกลางของระบบ | เก็บบัญชี ทักษะ งาน การสอบ และการแจ้งเตือน |
| บริการภายนอก | ผู้ให้ข้อมูลหรือเครื่องมือเฉพาะทาง | GitHub, ผู้ให้บริการงาน/คอร์ส, Judge0 และ Gemini |

ภาพรวมการเดินทางของข้อมูล:

~~~mermaid
flowchart LR
  People["ผู้สมัคร / บริษัท / ผู้ดูแล"] --> Web["หน้าเว็บ"]
  Web --> API["API ตรวจสิทธิ์และใช้กติกา"]
  API <--> DB[("ฐานข้อมูลกลาง")]
  API <--> Services["GitHub, แหล่งงาน/คอร์ส,<br/>Judge0, Gemini"]
  Timer["งานอัตโนมัติตามเวลา"] --> API
~~~

## 2. ผู้ใช้แต่ละกลุ่มทำอะไรได้บ้าง

### ผู้สมัคร

1. **สร้างบัญชีและโปรไฟล์** — ระบบสร้างบัญชีผู้ใช้ (User) และประวัติผู้สมัคร (CandidateProfile) ซึ่งเก็บชื่อ ประวัติ เป้าหมายอาชีพ การศึกษา และประสบการณ์
2. **เพิ่มหลักฐานทักษะจาก GitHub** — เมื่อเชื่อมชื่อบัญชี GitHub ระบบอ่าน repository และเทคโนโลยีที่พบ บันทึกเป็นประวัติโครงการและหลักฐานทักษะ
3. **ทำแบบประเมิน** — ข้อสอบอาจเป็นแบบเลือกคำตอบหรือเขียนโค้ด ผลสอบถูกเก็บไว้เพื่อแสดงคะแนนและป้ายรับรองทักษะ
4. **ค้นหาและเปรียบเทียบงาน** — ระบบเทียบทักษะของผู้สมัครกับรายการทักษะที่บริษัทระบุ พร้อมแสดงคะแนนความเหมาะสมและทักษะที่ยังขาด
5. **สมัครและติดตามผล** — ใบสมัครเก็บตำแหน่งที่สมัคร รอบการสมัคร สถานะปัจจุบัน ประวัติการเปลี่ยนสถานะ และคะแนนจับคู่ในวันที่สมัคร
6. **พัฒนาทักษะ** — ระบบเทียบคะแนนกับระดับเป้าหมายตามสายอาชีพ แล้วค้นหาคอร์สที่เกี่ยวข้อง

### บริษัท

1. **สร้างบัญชีบริษัท** — บัญชีบริษัทเชื่อมกับองค์กรผ่านข้อมูลสมาชิกบริษัท (CompanyMember) ระบบเริ่มสถานะการยืนยันไว้เป็นรอตรวจ
2. **ส่งข้อมูลยืนยันองค์กร** — บริษัทส่งเลขทะเบียนและเอกสาร เก็บเป็นคำขอตรวจสอบ (CompanyVerification) ให้ผู้ดูแลอนุมัติหรือปฏิเสธ
3. **ลงประกาศงาน** — ระบุรายละเอียด ตำแหน่ง สถานที่ เงินเดือน และเลือกทักษะที่ต้องการ แต่ละทักษะจะกำกับได้ว่าเป็นคุณสมบัติจำเป็นหรือคุณสมบัติเสริม
4. **ดูผู้สมัคร** — บริษัทเห็นผู้สมัครที่ยื่นสมัครตำแหน่งของบริษัท พร้อมโปรไฟล์ ทักษะ หลักฐาน GitHub และผลแบบประเมินที่เกี่ยวข้อง
5. **จัดการขั้นตอนรับสมัคร** — เปลี่ยนสถานะใบสมัคร เช่น กำลังพิจารณา นัดสัมภาษณ์ มอบหมายแบบทดสอบ เสนอจ้าง รับเข้าทำงาน หรือปฏิเสธ
6. **ประเมินผู้สมัคร** — บันทึกคะแนนด้านเทคนิค การแก้ปัญหา การสื่อสาร และการทำงานร่วมกัน พร้อมเขียนข้อเสนอแนะ

### ผู้ดูแลระบบ

ผู้ดูแลตรวจสอบบริษัทและผู้ใช้ ดูสถิติระบบ จัดการรายการทักษะมาตรฐานและแบบประเมิน รวมถึงสั่งดึงข้อมูลตำแหน่งงาน/คอร์สและอ่านรายงานผลการดึงข้อมูล

## 3. ส่วนต่าง ๆ ของระบบเชื่อมกันอย่างไร

คำว่า “โมดูล” หมายถึงส่วนงานที่รับผิดชอบเรื่องหนึ่ง เช่น การค้นหางานหรือการแจ้งเตือน โมดูลบางคู่เรียกใช้บริการของกันโดยตรง ส่วนใหญ่ส่งต่องานผ่านระเบียนในฐานข้อมูลกลาง

~~~mermaid
flowchart TD
  Profile["โปรไฟล์ผู้สมัคร"] --> GitHub["อ่าน GitHub"]
  GitHub --> Evidence["โครงการและหลักฐาน"]
  Evidence --> Skills["คะแนนทักษะของผู้สมัคร"]
  Test["แบบประเมิน"] --> Skills
  Skills --> Match["เปรียบเทียบกับงาน"]
  JobReq["ตำแหน่งงานและทักษะที่ต้องการ"] --> Match
  Match --> Apply["ใบสมัครและคะแนน ณ วันสมัคร"]
  Apply --> Pipeline["บริษัทเปลี่ยนสถานะ"]
  Pipeline --> Notice["แจ้งผู้สมัคร"]
  Pipeline --> AssignedTest["อาจมอบหมายแบบทดสอบ"]
  AssignedTest --> Test
  Pipeline --> Feedback["บันทึกผลประเมินบริษัท"]
  Skills --> Gap["หาทักษะที่ยังขาด"]
  Career["เป้าหมายอาชีพ"] --> Gap
  Gap --> Courses["คอร์สเรียนที่เกี่ยวข้อง"]
  JobSources["ข้อมูลจากบริษัท/เว็บงาน"] --> Import["นำเข้าข้อมูล"]
  CourseSources["ข้อมูลจาก YouTube/Udemy"] --> Import
  Import --> JobReq
  Import --> Courses
~~~

### จุดเชื่อมโดยตรงระหว่างโมดูล

การเชื่อมตรงต่อไปนี้เป็นการเรียกใช้ส่วนงานของอีกโมดูล:

- **การค้นหางาน** และ **การสมัครงาน** เรียกตัวคำนวณคะแนนจับคู่ร่วมกัน (MatchingService)
- **ส่วนของบริษัท** เรียกบริการโปรไฟล์ผู้สมัคร (CandidateService) เพื่อสร้างข้อมูลเรดาร์ทักษะ และเรียกบริการแจ้งเตือน (NotificationsService) เมื่อเปลี่ยนสถานะใบสมัคร
- **งานอัตโนมัติ** เรียกบริการนำเข้าและตรวจรายการปิดแล้ว (IngestionModule)
- **ทุกโมดูลที่ต้องอ่านหรือบันทึกข้อมูล** ใช้ Prisma เชื่อมกับฐานข้อมูลกลาง

ส่วนที่ไม่ได้เรียกกันโดยตรง เช่น GitHub กับ Matching จะส่งต่องานทางอ้อม: GitHub บันทึกทักษะลงฐานข้อมูล แล้ว Matching อ่านทักษะชุดนั้นเมื่อต้องเทียบงาน

แผนผังฉบับขยายที่ระบุชื่อข้อมูลบนแต่ละเส้นอยู่ใน [MODULE_DATA_FLOWS.md](MODULE_DATA_FLOWS.md)

## 4. แต่ละโมดูลรับผิดชอบอะไร

| โมดูล | อธิบายแบบทั่วไป | ข้อมูลหลักที่ใช้หรือเปลี่ยน | ส่งงานต่อให้ |
|---|---|---|---|
| บัญชีผู้ใช้ (AuthModule) | สมัคร เข้าสู่ระบบ และตรวจว่าใครเป็นผู้ใช้คนใด | User, CandidateProfile, Company, CompanyMember | ทุกหน้าที่ต้องรู้ตัวตนหรือบทบาทผู้ใช้ |
| โปรไฟล์ผู้สมัคร (CandidateModule) | แสดงและแก้ประวัติผู้สมัคร พร้อมสรุปทักษะเป็นเรดาร์ | CandidateProfile, CandidateSkill, GitHubRepository, GitHubEvidence, CompanyEvaluation, JobApplication | บริษัทใช้ดูผู้สมัคร; หน้าโปรไฟล์ใช้ดูประวัติและทักษะ |
| ข้อมูลบริษัทและรับสมัคร (CompanyModule) | จัดการองค์กร งาน ผู้สมัคร สถานะรับสมัคร และแบบทดสอบของบริษัท | Company, CompanyMember, CompanyVerification, Job, JobSkill, JobApplication, Assessment | ส่งสถานะใหม่ไปสร้าง Notification; ขอ radar จาก CandidateModule |
| หลังบ้านผู้ดูแล (AdminModule) | ตรวจบริษัทและดูแลข้อมูลส่วนกลางหลายประเภท | User, CompanyVerification, Skill, SkillFramework, Assessment, Course, Job, IngestionLog และข้อมูลสถิติ | ช่วยควบคุมข้อมูลที่ฟีเจอร์อื่นอ่านใช้ |
| รายการทักษะ (SkillsModule) | เปิดดูทักษะและกรอบมาตรฐานอาชีพ | Skill, SkillFramework, SkillFrameworkItem | ฟอร์มประกาศงาน แบบประเมิน และหน้าคอร์สใช้เป็นรายการตัวเลือก |
| เชื่อม GitHub (GithubModule) | อ่าน repository และหาเทคโนโลยีที่ผู้สมัครใช้ | CandidateProfile, GitHubRepository, GitHubEvidence, Skill, CandidateSkill | ป้อนข้อมูลทักษะให้โปรไฟล์ การจับคู่งาน และคำแนะนำ |
| แบบประเมิน (AssessmentsModule) | แสดงข้อสอบ เริ่มสอบ บันทึกคำตอบ ตรวจโค้ด และเก็บผล | Assessment, Question, Choice, AssessmentAttempt, AssessmentAnswer, CandidateSkill | ผลสอบแพลตฟอร์มช่วยยืนยัน CandidateSkill; ผลสอบบริษัทช่วยฝ่ายรับสมัคร |
| รายการงาน (JobsModule) | ค้น กรอง เรียง และดูรายละเอียดงาน พร้อมงานที่เข้ากับผู้ใช้ | Job, JobSkill, Company, CandidateProfile, JobFavorite, Course | เรียก MatchingModule เพื่อคำนวณคะแนน และแสดงคอร์สที่สัมพันธ์กับงาน |
| คะแนนจับคู่งาน (MatchingModule) | เปรียบเทียบคะแนนทักษะผู้สมัครกับสิ่งที่งานต้องการ | CandidateProfile/CandidateSkill และ Job/JobSkill | ส่งคะแนนให้ JobsModule แสดงผล และ ApplicationsModule เก็บตอนสมัคร |
| ใบสมัคร (ApplicationsModule) | สร้าง ยกเลิก และดูใบสมัครของผู้สมัคร | JobApplication, Job, CandidateProfile, ApplicationStatusHistory | ขอคะแนนจาก MatchingModule; บริษัทนำใบสมัครเดิมไปจัดการต่อ |
| ความเห็นบริษัท (EvaluationsModule) | เก็บ feedback ของผู้สมัครต่อใบสมัครงาน | CompanyMember, JobApplication, CompanyEvaluation, CandidateProfile | ผู้สมัครดู feedback ได้; ปัจจุบันไม่ได้ส่งคะแนนนี้ไปปรับ skill gap |
| คำแนะนำ (RecommendationsModule) | หาทักษะที่ควรพัฒนาและคอร์สที่เกี่ยวข้อง | CandidateProfile, CandidateSkill, Skill, Course, CourseSkill | นำผลไปแสดงบนหน้าคอร์ส/skill gap |
| นำเข้าข้อมูลงานและคอร์ส (IngestionModule) | ดึงข้อมูลภายนอก แปลงให้อยู่ในรูปของระบบ และติดแท็กทักษะ | Job, JobSkill, Course, CourseSkill, Skill, IngestionLog | JobsModule, SkillsModule และ RecommendationsModule นำข้อมูลไปใช้ |
| ตั้งเวลางาน (SchedulerModule) | เรียกการดึงข้อมูลและตรวจรายการปิดแล้วตามเวลาที่ตั้งไว้ | เรียก IngestionService และตัวตรวจงาน/คอร์ส | IngestionModule ทำงานและบันทึกผลรอบนั้น |
| แจ้งเตือน (NotificationsModule) | แสดงการแจ้งเตือนและสถานะว่าอ่านแล้วหรือยัง | Notification | CompanyModule สร้างการแจ้งเตือนเมื่อบริษัทเปลี่ยนสถานะ |
| ตรวจสุขภาพระบบ (HealthModule) | เช็กว่า API ติดต่อฐานข้อมูลได้หรือไม่ | คำสั่งทดสอบการเชื่อมต่อฐานข้อมูล | ระบบ deploy ใช้ตรวจความพร้อม |
| ประกอบระบบ (AppModule) | เปิดใช้งาน modules ทั้งหมดร่วมกัน | ไม่มีข้อมูลธุรกิจของตัวเอง | เป็นจุดรวมการตั้งค่าและส่วนงาน API |
| ชนิดข้อมูลที่ใช้ร่วมกัน (packages/shared) | ทำให้เว็บและ API ใช้ชื่อสถานะ/รูปแบบข้อมูลชุดเดียวกัน | enums และ interfaces เช่น role, สถานะใบสมัคร และคะแนนจับคู่ | ทั้งเว็บและ API |

## 5. ข้อมูลสำคัญเปรียบเหมือนแฟ้มกลาง

| ชื่อข้อมูล | ใช้เก็บอะไร | ใครสร้างหรือเปลี่ยน | ใครอ่านต่อ |
|---|---|---|---|
| User | อีเมล บทบาท วิธีเข้าสู่ระบบ และสถานะบัญชี | AuthModule, ผู้ดูแลบางรายการ | Auth และทุกหน้าที่ต้องตรวจสิทธิ์ |
| CandidateProfile | ชื่อ ประวัติ เป้าหมายอาชีพ GitHub และข้อมูลการศึกษา/ประสบการณ์ | ผู้สมัครผ่าน CandidateModule; AuthModule สร้างตอนสมัคร | GitHub, Matching, Applications, Recommendations, Company |
| Company / CompanyMember | ข้อมูลองค์กรและผู้ใช้ที่เป็นสมาชิกขององค์กร | AuthModule และ CompanyModule | บริษัท, ผู้ดูแล, รายการงาน |
| CompanyVerification | เลขทะเบียน เอกสาร สถานะตรวจ และเหตุผลปฏิเสธ | บริษัทส่งคำขอ; AdminModule ตรวจ | หน้าโปรไฟล์บริษัทและหลังบ้านผู้ดูแล |
| Skill | รายชื่อทักษะมาตรฐาน เช่น React หรือ PostgreSQL | AdminModule; GitHub/ingestion สร้างเพิ่มได้เมื่อพบชื่อใหม่ | โปรไฟล์ งาน แบบประเมิน และคำแนะนำ |
| CandidateSkill | คะแนนของผู้สมัครในแต่ละ Skill และสถานะยืนยัน | GitHubModule และ AssessmentsModule | Matching, Candidate, Recommendations, Company |
| GitHubRepository / GitHubEvidence | Repository ที่พบและเหตุผล/หลักฐานว่าพบ Skill นั้นในโครงการ | GithubModule | โปรไฟล์ผู้สมัครและบริษัทที่ดูใบสมัคร |
| Job / JobSkill | รายละเอียดงานและทักษะจำเป็น/เสริมของงาน | CompanyModule หรือ IngestionModule | Jobs, Matching, Applications |
| JobApplication | ผู้สมัครคนใดสมัครงานใด รอบที่เท่าไร คะแนนตอนสมัคร และสถานะ | ApplicationsModule; บริษัทเปลี่ยนสถานะผ่าน CompanyModule | ผู้สมัคร บริษัท และการแจ้งเตือน |
| ApplicationStatusHistory | บันทึกว่าเปลี่ยนจากสถานะใดเป็นสถานะใด เมื่อไร และมีหมายเหตุอะไร | ApplicationsModule และ CompanyModule | หน้า pipeline ของบริษัทและประวัติผู้สมัคร |
| Assessment / Attempt / Answer | แบบทดสอบ ข้อสอบ การเริ่มสอบ คำตอบ คะแนน และการ review | AdminModule/CompanyModule จัดทำข้อสอบ; AssessmentsModule บันทึกผลสอบ | ผู้สมัคร บริษัท และผู้ดูแล |
| CompanyEvaluation | คะแนน 1–5 ในหลายด้าน พร้อม feedback และจุดที่ควรพัฒนา | EvaluationsModule หลังบริษัทประเมิน | ผู้สมัครและหน้าดูผู้สมัครของบริษัทนั้น |
| Course / CourseSkill | คอร์สเรียนและทักษะที่คอร์สครอบคลุม | IngestionModule หรือข้อมูลตั้งต้น | หน้าคอร์สและคำแนะนำ |
| IngestionLog | สรุปว่ารอบนำเข้าข้อมูลสำเร็จหรือไม่ มีรายการใหม่/ซ้ำ/ผิดพลาดเท่าไร | Ingestion และตัวตรวจรายการปิดแล้ว | ผู้ดูแลระบบ |
| Notification | ข้อความแจ้งเตือน เจ้าของ ลิงก์ และสถานะอ่านแล้ว | NotificationsModule; ถูกเรียกโดย CompanyModule เมื่อเปลี่ยนสถานะ | กระดิ่งแจ้งเตือนของผู้ใช้ |

### ข้อมูลชุดหนึ่งเกี่ยวข้องกันอย่างไร

- ผู้สมัครหนึ่งคนมี **CandidateProfile** หนึ่งชุด แต่มี **CandidateSkill** ได้หลายรายการ เช่น หนึ่งรายการต่อหนึ่งทักษะ
- ทักษะหนึ่งรายการอาจเชื่อมกับผู้สมัครหลายคน งานหลายตำแหน่ง และคอร์สหลายรายการ
- งานหนึ่งตำแหน่งมี **JobSkill** หลายรายการ และมีผู้สมัครส่ง **JobApplication** ได้หลายคน
- ใบสมัครมีประวัติสถานะหลายรายการ แต่มี CompanyEvaluation ได้อย่างมากหนึ่งรายการตามโครงสร้างปัจจุบัน
- แบบประเมินหนึ่งชุดมีคำถามหลายข้อ ผู้สมัครทำข้อสอบเกิดเป็น attempt และแต่ละ attempt เก็บคำตอบได้หลายรายการ

## 6. คะแนนจับคู่และคำแนะนำทำงานอย่างไร

### คะแนนจับคู่งาน

ระบบให้ความสำคัญกับสามเรื่อง:

| ส่วนของคะแนน | น้ำหนัก | อธิบายง่าย ๆ |
|---|---:|---|
| ทักษะที่งานระบุว่าจำเป็น | 70% | มีทักษะตรงงานกี่ข้อ และคะแนนทักษะถึงระดับที่งานต้องการหรือไม่ |
| ทักษะเสริม | 20% | มีทักษะเสริมที่บริษัทมองหาอยู่หรือไม่ |
| เป้าหมายอาชีพ | 10% | ชื่ออาชีพที่ผู้สมัครตั้งไว้ใกล้เคียงกับชื่อตำแหน่งงานหรือไม่ |

คะแนนนี้ช่วยจัดลำดับและอธิบายเหตุผล ไม่ได้เป็นการรับประกันว่าจะได้รับการจ้าง บริษัทเป็นผู้ตัดสินใจในขั้นตอนรับสมัคร

### คะแนนทักษะไม่ใช่ตัวเลขเดียวกันทั้งหมด

- **คะแนนจากการใช้งานจริง (practicalScore):** ปัจจุบันได้จากการตรวจพบเทคโนโลยีใน GitHub และข้อมูล repository; ตัวจับคู่งานใช้คะแนนนี้เป็นหลักเมื่อมีค่า
- **คะแนนทฤษฎีและเขียนโค้ด (theoryScore/codingScore):** มาจากแบบประเมินของแพลตฟอร์ม
- **คะแนนยืนยัน (verifiedScore):** รวม practical 50%, theory 20%, coding 30% เพื่อประกอบการให้ badge/สถานะยืนยัน
- การจับคู่งานอ่านคะแนน practical ก่อน; ผลสอบจึงมีบทบาทเด่นในการยืนยัน badge และการวิเคราะห์ gap มากกว่าการเปลี่ยนคะแนนจับคู่โดยตรงเมื่อผู้สมัครมี practicalScore แล้ว

### Skill gap และคอร์สเรียน

RecommendationsModule เปรียบเทียบคะแนนกับระดับเป้าหมายที่เตรียมไว้สำหรับ Full Stack, Frontend, Backend และ DevOps หากยังไม่มีเป้าหมายที่ตรงรายการ จะใช้ Full Stack เป็นค่าเริ่มต้น แล้วค้นคอร์สจากชื่อ/คำอธิบายหรือความสัมพันธ์ระหว่างคอร์สกับทักษะ

หน้ารายละเอียดงานมีคำแนะนำคอร์สอีกทางหนึ่ง: ถ้าระบบรู้ทักษะที่ผู้สมัครยังขาดสำหรับงานนั้น ก็ใช้ทักษะเหล่านั้นค้นคอร์ส; ถ้ายังไม่มีข้อมูลผู้สมัคร จะเริ่มจากทักษะจำเป็นของตำแหน่งงาน

## 7. วงจรสมัครงานและการแจ้งเตือน

1. ผู้สมัครเลือกงานและส่งใบสมัคร
2. ระบบตรวจว่างานยังเปิดอยู่และตรวจว่ามีใบสมัครที่ยังดำเนินอยู่แล้วหรือไม่
3. ระบบคำนวณคะแนนจับคู่ ณ เวลานั้นและบันทึกเป็นข้อมูลประกอบของใบสมัคร
4. บริษัทเปิดดูผู้สมัครและขยับสถานะ เช่น REVIEWING, INTERVIEW หรือ TECHNICAL_TEST
5. เมื่อบริษัทเปลี่ยนสถานะ ระบบบันทึกประวัติและสร้าง Notification ให้ผู้สมัคร
6. ถ้ามีแบบทดสอบ บริษัทกำหนด Assessment ให้กับใบสมัคร ผู้สมัครทำข้อสอบ และผลสอบผูกกลับกับ AssessmentAttempt
7. บริษัทอาจบันทึก CompanyEvaluation แยกจากสถานะใบสมัคร

สถานะมีทั้งกำลังดำเนินการและผลลัพธ์สุดท้าย เช่น ACCEPTED, REJECTED หรือ CANCELLED หากใบสมัครถูกยกเลิกหรือถูกปฏิเสธ ผู้สมัครสมัครใหม่ได้โดยระบบเพิ่มหมายเลขรอบ (roundNumber) เพื่อเก็บประวัติเดิมไว้

## 8. การนำเข้าข้อมูลงานและคอร์ส

ระบบดึงข้อมูลงานจาก JSearch, JobsDB, JobThai, Blognone และ Remotive; คอร์สมาจาก YouTube และ Udemy จากนั้นจัดให้อยู่ในรูปแบบข้อมูลกลางของระบบและพยายามเชื่อมกับรายการ Skill ที่มีอยู่

รอบการทำงานหลักตามกำหนดเวลา Bangkok:

- 00:00 — ดึงข้อมูลงานและคอร์ส
- 00:30 — ตรวจและจัดการงานที่ปิดแล้ว
- 00:35 — ตรวจและจัดการคอร์สที่ปิดหรือถูกนำออก

ผู้ดูแลสามารถสั่งทำงานเหล่านี้เองจากหน้า admin ได้ด้วย ผลแต่ละรอบถูกเก็บใน IngestionLog เพื่อดูจำนวนที่เพิ่ม ซ้ำ หรือผิดพลาด

## 9. รายละเอียดที่ช่วยอ่านระบบให้ตรงกับโค้ดปัจจุบัน

- ผลประเมินจากบริษัทถูกบันทึกและผู้สมัครดูได้ แต่ยังไม่ถูกนำไปปรับ CandidateSkill หรือคำนวณ skill gap อัตโนมัติ
- คะแนนจับคู่ใช้งาน practicalScore ก่อน ส่วนคะแนนทฤษฎี/เขียนโค้ดช่วยสร้าง verifiedScore และ badge; จึงไม่ควรตีความว่า badge กับ match score เป็นคะแนนเดียวกัน
- ใน GitHub sync ปัจจุบันค่า commitCount และ linesOfCode ที่แสดงในหลักฐานถูกสร้างเป็นค่ากึ่งสุ่ม ไม่ได้คำนวณจากจำนวน commit และบรรทัดจริงใน repository
- คะแนน practicalScore จาก GitHub ปัจจุบันอิงจำนวนดาวและน้ำหนัก skill ที่ตรวจพบ โดยถูกจำกัดให้อยู่ระหว่าง 50–95
- แบบประเมินของบริษัทกับแบบประเมินทักษะของแพลตฟอร์มเก็บอยู่ในกลุ่มข้อมูล Assessment เดียวกัน แต่มีเจ้าของและวัตถุประสงค์ต่างกัน; โดยอัตโนมัติระบบปรับคะแนน CandidateSkill จากแบบประเมินของแพลตฟอร์มที่ผูก Skill เท่านั้น
- CompanyModule และ AdminModule จัดการข้อมูล Assessment โดยตรงผ่านฐานข้อมูล ส่วน AssessmentsModule รับผิดชอบการเริ่มสอบและบันทึกผล จึงเป็นการส่งต่องานผ่านข้อมูลร่วม ไม่ใช่การเรียก service เดียวกันทุกขั้น
